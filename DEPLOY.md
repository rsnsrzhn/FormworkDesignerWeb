# Публикация FormworkDesigner: по шагам

## 1. Что уже готово
React/Vite, Node 24, npm, prerender пяти страниц, API заявок через Resend, Vercel-конфигурация, заголовки безопасности и кеширование. Docker и база данных не нужны. `.env` создан из `.env.example`, остаётся локальным и исключён из Git. Значения в нём заполняете вы.

Vercel Hobby разрешён для личных некоммерческих сайтов. Этот лендинг предлагает приобретение приложения: для коммерческого запуска выберите подходящий тариф. Источник: https://vercel.com/docs/plans/hobby . Домен *.vercel.app не отменяет это условие.

## 2. Подготовьте почту
1. Создайте аккаунт Resend: https://resend.com . Это сервис доставки, не хостинг сайта.
2. Для реальных писем добавьте в Resend → Domains принадлежащий вам домен или отдельный поддомен отправки. Внесите показанные Resend DNS-записи у активного DNS-провайдера и дождитесь Verified. Не стирайте существующие MX/SPF/DKIM; следуйте точным записям сервиса. https://resend.com/docs/dashboard/domains/introduction .
3. Создайте API key с правом отправки, по возможности ограниченным вашим доменом. Сохраните ключ приватно.
4. Определите отправителя на подтверждённом домене (`INQUIRY_FROM`) и ваш реальный ящик получателя (`INQUIRY_TO`). Получатель может быть обычной вашей почтой. Пароль от этого ящика сайту не нужен.
5. Адрес *.vercel.app нельзя подтвердить как собственный почтовый домен. Если своего домена ещё нет, сайт можно сначала опубликовать с `ACCEPT_INQUIRIES=false`; форма не будет отправлять письма. Тестовый отправитель Resend не заменяет production-настройку для произвольных получателей.

## 3. Локальная конфигурация
Откройте `.env` в редакторе. Не отправляйте его в чат, Git или screenshots.

| Переменная | Что указать |
|---|---|
| SITE_URL | Пока пусто; после первого деплоя — реальный production HTTPS адрес без пути |
| ACCEPT_INQUIRIES | Сначала false. true только после настройки доставки и данных оператора |
| RESEND_API_KEY | Ключ Resend |
| INQUIRY_FROM | Адрес отправителя на подтверждённом домене |
| INQUIRY_TO | Ваш ящик для заявок |
| OPERATOR_NAME | Реальное имя/наименование ответственного за обработку |
| OPERATOR_ADDRESS | Реальные данные адреса оператора |
| PRIVACY_EMAIL | Контакт по персональным данным, на который можно написать |
| POLICY_VERSION | Оставьте значение примера; меняйте при обновлении условий |
| PUBLIC_ORIGIN | Оставьте пустым; дополнительный origin обычно не нужен |

Данные оператора публикуются на правовых страницах. Почтовый API key и получатель остаются серверными. Не используйте VITE_ для секретов.

В терминале проекта:

```bash
npm run deploy:check
npm run build
npm test
npm run test:browser
```

`deploy:check` сообщает только названия незаполненных переменных, проверяет формат SITE_URL; писем не отправляет. Это проверка конфигурации, не проверка DNS/доставки/юридической достаточности документов.
Для просмотра: `npm run dev`, http://localhost:5173, остановка Ctrl+C. Перезапускайте сервер после изменения .env. Если порт занят, остановите прежний сервер; не запускайте несколько копий.

## 4. Отправьте код в свой Git
Коммиты уже созданы локально. Убедитесь, что выбран ваш нужный приватный/публичный репозиторий:

```bash
git status --short
git remote -v
git branch --show-current
git log -3 --oneline
```

Если remote уже настроен, отправьте текущую ветку: `git push -u origin HEAD`. Если remote отсутствует, создайте пустой репозиторий в GitHub и выполните команду `git remote add origin ...` с его настоящим URL, затем push. Не подставляйте чужой URL. Права/токены в remote URL не вставляйте. Не выполняйте `git add .` ради деплоя: локальные навыки сейчас оставлены отдельно и сайту не нужны. .env, node_modules, dist и установщик не коммитьте.

## 5. Создайте проект Vercel
1. Войдите в Vercel, выберите подходящий тариф, Add New → Project.
2. Подключите GitHub и импортируйте репозиторий. Root Directory — корень проекта.
3. Проверьте Framework Vite, Node.js 24.x, Install `npm ci`, Build `npm run build`, Output `dist`. Они согласованы с package.json/vercel.json. Ничего отдельно в dist загружать не надо.
4. В Environment Variables задайте переменные из таблицы для **Production**. `.env` с вашего компьютера через Git не переносится. В интерфейсе вводите чистые значения без окружающих кавычек.
5. Пока не закончены почта и защита формы, оставьте ACCEPT_INQUIRIES=false. Для Preview не добавляйте production почтовый ключ и оставьте приём выключенным.
6. Deploy. Откройте production deployment. Vercel выдаст адрес проекта *.vercel.app. Не путайте его с адресом отдельной preview-сборки.
7. Settings → Environment Variables: задайте SITE_URL как фактический production адрес с https://, без пути. Deployments → Redeploy. Альтернатива — системная VERCEL_PROJECT_PRODUCTION_URL, если включена. Новые env действуют после нового deployment. https://vercel.com/docs/environment-variables .
8. Убедитесь, что production открыт посетителю без входа в Vercel; preview можно оставить защищённым.

## 6. Включите заявки
1. Проверьте подтверждённый отправитель Resend, получателя и опубликованные данные оператора. Уточните сроки хранения/условия обработки персональных данных для вашей деятельности, не публикуйте выдуманные реквизиты.
2. В Vercel Firewall добавьте rate limit для POST /api/inquiries по IP, например 5 запросов за 60 секунд. Доступность и стоимость правила проверьте для своего тарифа. Кодовый лимит на процесс не является распределённой защитой от спама.
3. Production ACCEPT_INQUIRIES=true, Redeploy.
4. Отправьте вручную одну заявку с собственными контактами и согласием. Проверьте письмо во Входящих/Спаме, затем событие доставки в Resend. Автотесты используют mock и не подтверждают реальную доставку.
5. Если приходит ошибка, не выключайте проверки сервера: проверьте Vercel Function Logs и Resend Events. При проблеме можно вернуть ACCEPT_INQUIRIES=false и Redeploy.

## 7. Подключите купленный домен (необязательно для просмотра сайта)
1. Vercel → Project → Settings → Domains → Add Domain. Добавьте ваш домен и www, если требуется.
2. У регистратора/активного DNS-провайдера внесите **точные** A/CNAME/TXT из Vercel. Не копируйте IP из чужих инструкций, не удаляйте почтовые записи Resend и существующего ящика. Смена NS не обязательна.
3. Дождитесь Valid Configuration и HTTPS. Выберите основной домен; второй вариант настройте редиректом на него.
4. Замените Production SITE_URL на основной адрес с https:// и сделайте Redeploy. Если PUBLIC_ORIGIN пуст, менять его не надо.
5. Откройте основной адрес и www, проверьте HTTPS и редирект. Регистрация/продление домена остаются отдельной обязанностью у регистратора. https://vercel.com/docs/domains/working-with-domains/add-a-domain .

## 8. Финальная проверка
Откройте напрямую /, /purchase, /contact, /privacy, /consent. /faq должен перенаправить на /, неизвестный URL вернуть 404. Проверьте телефон, меню, переключение и воспроизведение роликов, форму и письмо. Проверьте /robots.txt и /sitemap.xml, canonical в исходном HTML. Production не должен иметь noindex. После выбора основного адреса можно подключить Google Search Console и Яндекс Вебмастер.

Проверьте Usage/лимиты трафика в Vercel и квоты Resend. Видео короткие, preload=none, autoplay отсутствует; но трафик не безлимитен. Новые изменения отправляются в production-ветку и разворачиваются Git-интеграцией. При ошибке используйте предыдущий deployment/откат коммитом. DNS при каждом обновлении менять не нужно.

Что нельзя завершить только локальным кодом: создание аккаунтов, подтверждение вашего домена, выдача API key, данные оператора, настройка тарифов/Firewall и реальная проверка письма. Эти действия выполняются в ваших аккаунтах. Секреты в чат не присылайте.
