# FormworkDesigner

Русскоязычный сайт программы для проектирования опалубки: демонстрации реального интерфейса, описание возможностей, приобретение и индивидуальная доработка, FAQ и заявка на сотрудничество.

**React + TypeScript · ASP.NET Core 10 · SQLite · Docker · Nginx**

Приложение доступно на десктопе и Android. На сайте показаны демонстрации настольной версии; возможности каждой версии обсуждаются с клиентом. Визуальная концепция сайта описана в [blue-redesign.md](docs/blue-redesign.md).

Без аккаунтов, онлайн-оплаты и публичного скачивания программы. Медиа размещаются на диске сервера; отдельное облачное хранилище не требуется.

## Структура

```text
FormworkDesignerWeb.sln
FormworkDesignerWeb/          Основной ASP.NET Core-проект
  ClientApp/                 React: страницы, компоненты, стили и тесты
  Features/Inquiries/        Заявки: валидация, SQLite, очистка данных
  Configuration/             Настройки приложения
  Properties/                Профили запуска Rider/.NET
  Program.cs                 Настройка HTTP API и зависимостей
tests/                       Проверки сервера и API
scripts/                     Общий запуск и подготовка медиа
deploy/                      Nginx, Docker фронтенда, пример HTTPS
docs/                        Архитектура и эксплуатация
```

SQLite содержит только заявки. API не предоставляет чтение заявок через интернет. Запись параметризована; повторная отправка с тем же идентификатором не создаёт дубликат. Действуют ограничения размера запроса и частоты отправки, проверка origin и honeypot. Контакты посетителей не записываются в прикладные логи.

Приложение организовано по функциям: серверный сценарий заявок находится в `Features/Inquiries`, клиентский интерфейс — в `ClientApp`. Для этого масштаба отдельные сборки Domain/Application/Infrastructure не требуются. Клиентские зависимости и результат сборки исключены из элементов .NET-проекта; React собирается отдельно и раздаётся Nginx.

## Локальный запуск

Нужны Node.js 24, npm и .NET SDK 10. Восстановление зависимостей требует доступа к npm и NuGet.

### Быстрый запуск из Rider

Откройте `FormworkDesignerWeb.sln` из корня репозитория. React физически расположен внутри основного проекта в `FormworkDesignerWeb/ClientApp` и отображается в Rider под этим проектом. Рядом в решении находятся `Tests`, `Deployment` и `Solution Items` с командами запуска. Если решение уже открыто, перезагрузите его после изменения `.sln`.

В терминале Rider из каталога, содержащего `.sln`, выполните:

```bash
npm run dev
```

Команда при необходимости установит зависимости фронтенда, соберёт интерфейс и API и запустит оба процесса. Откройте **http://localhost:5173**. Остановка — `Ctrl+C`. Корневой `package.json` также добавлен в `Solution Items`: скрипт `dev` можно запускать через действие Run в Rider.

Запуск показывает три этапа: сборка React, восстановление NuGet и сборка API без повторного восстановления. Если NuGet не отвечает, запуск прерывается через 120 секунд с сообщением. Для медленного соединения можно задать `RESTORE_TIMEOUT_MS` (не более 600000).

Чтобы посмотреть интерфейс отдельно, без восстановления .NET-пакетов и запуска API:

```bash
npm run preview
```

Адрес тот же: **http://localhost:5173**. Возможности программы, видео, покупка и FAQ доступны; форма не отправляет заявки без работающего API. В этом режиме ответы сервера и сохранение не имитируются.

Профиль `.NET` **FormworkDesigner API** запускает только сервер на `http://localhost:5080`. Для отдельной отладки API запустите этот профиль и фронтенд отдельной командой `npm run dev --prefix FormworkDesignerWeb/ClientApp`. При первом запуске обязательно дождитесь восстановления NuGet-пакетов; при ошибке сборки сайт не запускается.

### Раздельный запуск

Если Rider показывает красные **названия файлов**, проверьте `git status`: статус `??` означает, что файлы ещё не добавлены в Git. После проверки исключений выполните `git add .` в своём терминале. Это отличается от подчёркиваний ошибок внутри кода.

Если подчёркнут `Microsoft.Data.Sqlite` или сборка сообщает `NU1101` / `NU1301`, сначала восстановите зависимости:

```bash
dotnet restore FormworkDesignerWeb.sln
```

Для восстановления нужен доступ к `https://api.nuget.org/v3/index.json`. Если восстановление не завершилось успешно, сначала устраните указанную ошибку доступа к NuGet; перенос папок и сброс кэшей IDE её не исправляют.

Если недоступен именно nuget.org, можно явно попробовать публичный источник Microsoft `dotnet-public`:

```bash
dotnet restore FormworkDesignerWeb.sln --configfile NuGet.Microsoft.Config --verbosity normal
```

Конфигурация применяется только этой командой и не меняет глобальные настройки. Доступ к `pkgs.dev.azure.com` также необходим. После успешного восстановления можно собрать API без повторного обращения к источникам: `dotnet build FormworkDesignerWeb --no-restore`. Если оба адреса недоступны, требуется диагностика DNS, соединения или прокси в окружении запуска Rider.

```bash
npm ci --prefix FormworkDesignerWeb/ClientApp
npm run build --prefix FormworkDesignerWeb/ClientApp
node scripts/prepare-media.mjs

ASPNETCORE_ENVIRONMENT=Development dotnet run --project FormworkDesignerWeb --no-launch-profile --urls http://localhost:5080
```

В другом терминале:

```bash
npm run dev --prefix FormworkDesignerWeb/ClientApp
```

Открыть **http://localhost:5173**. Сервер preview проксирует `/api/` на порт 5080 и берёт медиа из исходной папки. Для другого адреса задайте `API_URL`, `PORT` и `MEDIA_DIRECTORY`. После изменения фронтенда повторите `npm run build`: preview раздаёт собранные файлы, HMR не используется.

Для локального API установите `ASPNETCORE_ENVIRONMENT=Development`. В этом режиме форма принимает только тестовые данные, о чём сообщает интерфейс. Если SDK установлен в `~/.dotnet`, добавьте эту папку в `PATH`. ASP.NET Core не читает `.env` автоматически: локальные значения передавайте как переменные окружения с разделителем `__`.

## Медиа

Фото, видео, EXE, SQLite, резервные копии и `.env` исключены из Git и Docker build context. После клонирования добавьте исходные материалы отдельно:

```bash
node scripts/prepare-media.mjs /path/to/opalubka-roliki-2026-11-02 ./media
```

Скрипт копирует только пять пар JPG/MP4 с именами `01-primery`, `02-razbivka`, `03-vysota`, `04-list`, `05-risovanie`. Установщик не копируется и не раздаётся. Шрифт Onest собирается из пакета Fontsource и загружается с самого сайта, без запросов к Google Fonts.

## Проверки

```bash
npm test --prefix FormworkDesignerWeb/ClientApp
npm run build --prefix FormworkDesignerWeb/ClientApp
dotnet run --project tests/ValidationTests
dotnet build FormworkDesignerWeb -c Release
node tests/api/inquiries.mjs
node FormworkDesignerWeb/ClientApp/node_modules/playwright/cli.js install chromium
FILE_PREVIEW=1 npm run test:browser --prefix FormworkDesignerWeb/ClientApp
```

`npm test` проверяет клиентскую валидацию и рендер страниц. API-тест запускает настоящий сервер с временной SQLite, проверяет сохранение, идемпотентность, ограничения, экспорт и восстановление резервной копии. Для SDK вне `PATH` задайте `DOTNET_BIN`.

Браузерный тест проверяет интерфейс с **имитацией ответов API**; сохранение подтверждается отдельными API-тестами. В режиме `FILE_PREVIEW=1` статические файлы передаются браузеру без локального HTTP-сервера; иначе нужен запущенный preview. Можно задать `CHROME_PATH` и `PREVIEW_URL`. На CI, где медиа намеренно отсутствуют, проверяется резервное отображение. Визуально проверить реальные ролики нужно на машине с материалами.

GitHub Actions выполняет сборки, тесты и Docker build. Ограничения проверок в среде разработки записаны в [verification.md](docs/verification.md).

## Развёртывание

Подойдёт один Linux VPS с Docker Compose и постоянным локальным диском. Не используйте эфемерную файловую систему или несколько экземпляров API с одной SQLite. Ориентир ресурсов для старта — 1–2 ГБ RAM; итог зависит от окружения и трафика.

1. Склонируйте проект и скопируйте `.env.example` в `.env`.
2. Подготовьте `media/` и каталог `data/`. Дайте пользователю контейнера .NET (UID 1654 в официальном образе) право записи в `data/`: `sudo install -d -m 700 -o 1654 -g 1654 data`. Уточните UID, если меняете базовый образ.
3. Настройте `PUBLIC_ORIGIN` на окончательный HTTPS-адрес без завершающего слеша. `HTTP_PORT` по умолчанию 8080.
4. Выполните `docker compose up -d --build`.
5. Настройте домен на IP сервера и HTTPS через Caddy на хосте по примеру [Caddyfile.example](deploy/Caddyfile.example). Docker публикует сайт только на `127.0.0.1:8080`; наружу открываются 80/443 через Caddy.
6. Проверьте `curl http://127.0.0.1:8080/api/health`, сайт через HTTPS и сохранение тестовой заявки.

Docker-сеть `172.30.67.0/24` задаёт доверенный адрес Nginx для корректного ограничения запросов по IP. При изменении сети измените `TrustedProxy` и `set_real_ip_from` согласованно. Caddy на хосте передаёт IP в `X-Forwarded-For`; Nginx доверяет только шлюзу этой сети. Не открывайте внутренний порт напрямую в интернет.

Медиа монтируются только для чтения, база — в отдельный каталог. Пересборка контейнеров не удаляет их. Для обновления: получите изменения, выполните `docker compose up -d --build`, проверьте health и форму. Перед обновлением API сделайте резервную копию. Для отката используйте предыдущий Git-коммит и сохранённую совместимую копию базы; автоматических разрушительных миграций нет.

### Включение приёма заявок

По умолчанию production-приём **отключён**. Перед включением:

- Заполните `OPERATOR_NAME`, `OPERATOR_ADDRESS`, `PRIVACY_EMAIL`.
- Завершите текст политики: хостинг и его регион, уполномоченные лица, передача данных, порядок обращений и сроки. Проверьте требования Беларуси и применимые требования к данным граждан РФ.
- Согласуйте `RETENTION_MONTHS` (по умолчанию 12), `POLICY_VERSION` и сохраните опубликованные редакции документов.
- Установите `LEGAL_REVIEWED=true` и `ACCEPT_INQUIRIES=true`, пересоздайте контейнер API.

Это не универсальный юридический документ: реквизиты оператора и условия фактического размещения должны соответствовать вашей работе. Пока сведения отсутствуют, сайт явно показывает статус подготовки документов и не принимает реальные заявки.

Переменные `.env` относятся к Docker Compose. Они не должны попадать в Git; `.env.example` содержит только образцы. Не передавайте реальные контакты через CI, issue и логи.

## Работа с заявками и резервирование

Административного кабинета нет. Команды доступны владельцу сервера через SSH:

```bash
docker compose exec api dotnet FormworkDesignerWeb.dll export /data/inquiries.csv
docker compose exec api dotnet FormworkDesignerWeb.dll backup /data/backup.db
docker compose exec api dotnet FormworkDesignerWeb.dll purge
docker compose exec api dotnet FormworkDesignerWeb.dll delete UUID_ЗАЯВКИ
```

Экспорт и backup отказываются перезаписывать существующий файл. Используйте разные имена. CSV защищён от интерпретации значений как формул. Скопируйте экспорт себе по защищённому каналу и удалите его с сервера после использования.

Резервирование использует SQLite backup API и допустимо при работающем API. **Не копируйте только `inquiries.db` работающей WAL-базы.** Рекомендуется ежедневное резервирование через cron с уникальным именем, копией вне сервера и согласованным сроком удаления. Защищайте копии так же, как базу, и учитывайте удаление данных по обращениям при восстановлении.

Проверка восстановления: остановите API, сохраните прежний каталог `data/`, восстановите backup под именем `inquiries.db` в новый каталог без старых `-wal`/`-shm`, установите владельца 1654, запустите API и проверьте экспорт. Никогда не заменяйте основной файл при открытых соединениях. Очистка просроченных заявок выполняется при запуске и каждые 24 часа; после восстановления повторите `purge` и примените поступившие требования об удалении.
