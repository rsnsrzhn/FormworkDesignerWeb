# FormworkDesigner

Русскоязычный сайт приложения для проектирования опалубки. React + TypeScript,
Node.js 24, Vite. Развёртывание на Vercel. C#, .NET SDK, Rider, Docker и база данных
для запуска не нужны.

На главной — крупный настоящий интерфейс, записи рабочих сценариев, пример документов и честное описание демоверсии. Продуктовые основания: `PRODUCT.md`; визуальная система: `DESIGN.md`. Неподтверждённое обещание экономии времени удалено.

## Запуск

Проект находится в `~/Projects/FormworkDesignerWeb`.

```bash
cd ~/Projects/FormworkDesignerWeb
npm ci
npm run dev
```

Открыть **http://localhost:5173**. Dev-сервер поддерживает HMR, серверный рендер
страниц и локальные Node.js API. Остановка — `Ctrl+C`. При необходимости задать
`PORT`. Пакетный менеджер — npm; `package-lock.json` хранится в Git.

Для проверки production-сборки:

```bash
npm run build
npm run preview
```

Открыть **http://localhost:4173**. Preview раздаёт `dist`, корректно возвращает 404
и запускает те же обработчики API, что используются в функциях Vercel. Это
локальная проверка; Vercel не запускает этот preview-сервер.

## Структура

```text
src/
  components/     Навигация и просмотр реальных роликов
  pages/          Главная, сотрудничество, форма и информация о данных
  lib/            API-клиент, валидация и анимация при прокрутке
  site.ts         Метаданные страниц
  entry-server.tsx  React-рендер при сборке
server/           Node-обработчики, доставка заявок, публичная конфигурация
api/              Точки входа Vercel Functions
scripts/          Локальный запуск, сборка, HTML/SEO и генерация social preview
tests/            Проверки API, рендера, первого кадра и браузерных сценариев
public/           Видео, обложки, чертёжный фон, favicon и social preview
docs/             Аудит, решения и подробная инструкция деплоя
vercel.json       Параметры сборки, URL и HTTP-заголовки
```

Пять страниц генерируются в HTML во время сборки. React добавляет интерактивность
через гидратацию; навигация использует обычные ссылки. Постоянно работающий сервер
для выдачи страниц не нужен. Неизвестный адрес возвращает HTTP 404, а не пустую SPA.

## SEO и адрес сайта

Для локальной проверки можно создать `.env` из `.env.example` и указать
`SITE_URL=https://ваш-домен`. При развёртывании Vercel используется `SITE_URL`,
а если он пуст — системная `VERCEL_PROJECT_PRODUCTION_URL`. Для первого релиза
подойдёт настоящий production-адрес `https://имя-проекта.vercel.app`.

Если системная переменная недоступна, задать `SITE_URL` явно и пересобрать проект.
Без известного адреса сборка не выдумывает canonical и не добавляет чужой домен
в sitemap. После подключения собственного домена обновить `SITE_URL` и сделать
новый deployment.

В готовом HTML есть отдельные title/description, Open Graph, canonical при
настроенном адресе и SoftwareApplication без вымышленных рейтингов/цен.
`sitemap.xml` и `robots.txt` создаются при сборке. Preview-развёртывания получают
`noindex`; production должен быть доступен поисковым роботам и посетителям без
входа в Vercel. Метатеги не гарантируют индексацию или определённую позицию.

## Заявки

Сайт умеет передавать заявки через Resend HTTP API. Постоянная SQLite не
используется. **Пока почтовые настройки не заполнены, отправка недоступна**:
никаких фиктивных успешных заявок и скрытой потери данных.

Переменные добавляются в `.env` для локальной работы или в Settings → Environment
Variables проекта Vercel для деплоя. Секреты не передавать в чат и не коммитить.

| Переменная | Назначение |
| --- | --- |
| `ACCEPT_INQUIRIES` | `true` для включения после настройки доставки |
| `RESEND_API_KEY` | Серверный ключ выбранного аккаунта Resend |
| `INQUIRY_FROM` | Разрешённый Resend адрес отправителя |
| `INQUIRY_TO` | Email получателя заявок |
| `OPERATOR_NAME` | Кто отвечает за обработку обращений |
| `OPERATOR_ADDRESS` | Адрес, если требуется для опубликованных сведений |
| `PRIVACY_EMAIL` | Контакт для вопросов об обработке данных |
| `POLICY_VERSION` | По умолчанию `2026-11-09` |
| `SITE_URL` | Основной адрес для canonical и sitemap |
| `PUBLIC_ORIGIN` | Дополнительный доверенный origin; обычно не нужен |

Ключи почтового API никогда не получают префикс `VITE_` и не попадают в браузер.
`GET /api/site-config` возвращает только публичные настройки.

Клиент и сервер проверяют контакты и отдельное согласие; сервер проверяет origin,
тип и размер запроса, honeypot и версию условий. Лимит в Node-процессе — пять
попыток в минуту на клиента; это базовая защита одного экземпляра, а не глобальный
распределённый лимит. Для публичного трафика доступна дополнительная настройка
правила на `/api/inquiries` в Vercel Firewall. Idempotency-Key передаётся Resend
для повторных попыток. Успех означает принятие сообщения почтовым API, а не
гарантированное попадание письма во входящие.

Тексты об обработке данных — сведения о фактической схеме, их нужно дополнить
контактами владельца и согласованными условиями до включения реального приёма.
Почтовый сервис и ящик имеют собственные настройки хранения. Автоматическое
удаление сообщений через 12 месяцев не реализовано и не обещается.

## Медиа и шрифты

Пять пар MP4/JPG в `public/media` входят в Git и автоматически попадают в Vercel.
Видео загружается при приближении к блоку, не запускается автоматически и имеет
управление воспроизведением. Исходные установщики не публикуются.

IBM Plex Sans с кириллицей и латиницей загружается с самого сайта через Fontsource;
запросов к Google Fonts нет. Лицензия — `public/font-license.txt`.
`public/social-preview.png` — готовая картинка для ссылок, 1200 × 630.
Для её повторной генерации после изменения SVG:

```bash
npm run social
```

Команда использует установленный Chromium/Chrome; если его нет, сначала выполнить
`npx playwright install chromium`.

## Проверки

```bash
npm test
npm run build
npm run test:browser
npm run format:check
```

Браузерный тест сам запускает production-preview на 4173 и останавливает его.
Можно передать `PREVIEW_URL` для существующего preview. При отсутствии браузера
выполнить `npx playwright install chromium`; для своего Chrome задать `CHROME_PATH`.
Проверяются первый кадр без JavaScript, новый шрифт, выбор видео, форма, FAQ,
HTTP 404, прямые URL, отсутствие
горизонтального скролла на пяти размерах экрана и одинаковая геометрия полей.
Результаты — в игнорируемом `test-results/`. Реальные письма тесты не отправляют.

## Переходы и первый кадр

CSS подключается отдельным блокирующим отрисовку stylesheet в `<head>`, а не
ожидает загрузки JavaScript. У SVG-логотипа также есть явные width/height.
Это предотвращает показ неоформленной страницы и огромного логотипа в dev.

Переходы между страницами используют нативные cross-document View Transitions
в поддерживающих их браузерах. Навигация остаётся обычной ссылкой; в остальных
браузерах страницы открываются стандартно. При прокрутке секции мягко появляются,
якорные ссылки прокручиваются плавно. Системное уменьшение движения отключает
все эти анимации. Нет перехвата колеса мыши и задержек перед переходом.

## Если VS Code пишет про C# или .NET SDK

В проекте нет `.cs`, `.csproj`, `.sln`, NuGet и команд `dotnet`. Запускать
нужно `npm run dev`, открыв именно `~/Projects/FormworkDesignerWeb`.

Найденное в локальном Output сообщение «The .NET SDK cannot be located»
создаёт расширение `ms-dotnettools.csharp`, а не сборка сайта. В Extensions
(`Ctrl+Shift+X`) выберите C# и C# Dev Kit → шестерёнка → **Disable (Workspace)**,
затем выполните **Developer: Reload Window**. Это отключает их для данного
проекта, не удаляя поддержку C# для других проектов. Устанавливать .NET ради
этого сайта не требуется. Если Problems всё ещё красный, откройте панель
`Ctrl+Shift+M` и проверьте конкретный файл и текст диагностики.
