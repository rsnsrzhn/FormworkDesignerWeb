# Публикация: сначала адрес Vercel, затем собственный домен

Обновлено: 2026-11-09. Сайт переведён на React/TypeScript/Vite и Node.js 24.
Проект находится в `~/Projects/FormworkDesignerWeb`. Эта инструкция описывает
действия в аккаунтах владельца: сам проект Vercel здесь ещё не создан,
публичный адрес не получен, домен не куплен и DNS не изменён.

## 1. Можно ли начать бесплатно

Для личного **действительно некоммерческого** хобби-проекта можно начать с Hobby.
У сайта будет адрес вида `https://имя-проекта.vercel.app`; отдельный домен покупать
для проверки не требуется. Конкретное имя зависит от доступности.
[Адреса Vercel](https://vercel.com/docs/domains/working-with-domains).

По условиям Vercel Hobby рассчитан на личное некоммерческое использование.
Решающим является фактическое использование: название «хобби» само по себе не
меняет условия. На сайте сейчас есть предложения о приобретении и доработке
программы. Если сайт используется для продаж или продвижения платных услуг,
нужно проверить применимость Hobby и при необходимости выбрать подходящий тариф.
На этапе знакомства не оформляем платную подписку автоматически.
[Условия Hobby](https://vercel.com/docs/plans/hobby).

При росте отдельно проверять расходы на хостинг, домен и доставку заявок.
Текущие цены, лимиты и включённые ресурсы — на [странице тарифов](https://vercel.com/pricing).
Наличие адреса `.vercel.app` не означает бесплатную регистрацию своего `.com`.

## 2. Что подготовлено в репозитории

- Root Directory — корень репозитория, не прежний `ClientApp`.
- Node.js — `24.x`, установлен в `package.json`.
- Framework Preset — Vite.
- Install Command — `npm ci`.
- Build Command — `npm run build`.
- Output Directory — `dist`.
- Настройки URL/HTTP-заголовков — `vercel.json`.
- Шесть страниц заранее генерируются в HTML; React добавляет интерактивность.
- `api/site-config.ts` и `api/inquiries.ts` — Node.js-функции Vercel.
- Обложки и ролики в `public/media` входят в Git и не требуют ручной загрузки.
- `.env`, зависимости, сборки, IDE-кэши и тестовые скриншоты не коммитятся.

Vercel поддерживает этот способ [развёртывания Vite](https://vercel.com/docs/frameworks/frontend/vite).
Постоянно работающий Node-сервер, .NET, Docker и VPS для сайта не нужны.

## 3. Первое развёртывание через GitHub

1. Войти в Vercel своим аккаунтом. Включить двухфакторную защиту.
2. Выбрать добавление нового проекта и импорт Git-репозитория.
3. Подключить GitHub. Если репозиторий не виден, в GitHub-настройках приложения
   Vercel разрешить доступ к `rsnsrzhn/FormworkDesignerWeb`.
4. Выбрать этот репозиторий. Разрешать доступ ко всем репозиториям необязательно.
5. Проверить параметры из предыдущего раздела. Не указывать старый вложенный путь.
6. Проверить production-ветку. Проект изначально находился на `dev`; для первого
   запуска выбрать отправленную ветку с завершённой миграцией. Если это `dev`,
   указать её в Settings → Environments / Git → Production Branch. Не полагаться
   на автоматическое предположение, что нужная ветка называется `main`.
7. На первом шаге можно оставить `ACCEPT_INQUIRIES=false` и не добавлять почтовые
   ключи: лендинг и видеодемонстрации будут работать, отправка заявки — явно недоступна.
8. В Settings → Environment Variables проверить доступность системных переменных
   Vercel. Для SEO используется `VERCEL_PROJECT_PRODUCTION_URL`, если `SITE_URL`
   не задан вручную. Если production-адрес ещё неизвестен, сначала развернуть сайт,
   скопировать стабильный адрес и добавить его в `SITE_URL` для Production.
9. Нажать Deploy, дождаться статуса Ready и проверить build logs.
10. Если после первого развёртывания добавили или изменили `SITE_URL`, запустить
    Redeploy. Canonical и sitemap создаются при сборке и сами после изменения
    переменной не переписываются.

Пример `SITE_URL`: `https://formworkdesigner.vercel.app` — только если **именно этот**
адрес выдан вашему проекту. Не копировать пример как готовую настройку.

Vercel подключает развёртывания к Git: обновление production-ветки публикует
новую production-версию; другие ветки и pull requests дают Preview.
[Git-интеграция](https://vercel.com/docs/git),
[окружения](https://vercel.com/docs/deployments/environments).

## 4. Какой из адресов открывать

У проекта могут быть стабильный production-адрес и отдельные адреса конкретных
сборок/веток. Для постоянных ссылок использовать адрес из Settings → Domains,
назначенный production-проекту. Для проверки нового коммита — адрес его Preview.

Например:

| Адрес | Назначение |
| --- | --- |
| `имя-проекта.vercel.app` | Постоянный адрес проекта до подключения своего домена |
| Адрес конкретного deployment | Проверка определённой сборки |
| `ваш-домен.com` | Собственный адрес после подключения |

Примеры не означают, что конкретное имя свободно.

Для публичного лендинга production должен открываться без аккаунта Vercel.
Проверить адрес в приватном окне браузера. Если появляется вход в Vercel,
проверить Settings → Deployment Protection и доступ именно к production.
Preview можно оставить защищённым.
[Защита развёртываний](https://vercel.com/docs/deployment-protection).

## 5. Как проверить бесплатный адрес

После статуса Ready:

1. Открыть production-адрес в приватном окне без входа в Vercel.
2. Проверить главную, шрифт, иллюстрацию и воспроизведение ролика.
3. Проверить видео: переключить «Контур», «Раскладка», «Высота», «Документы»,
   запустить и остановить ролик. Проверить переход к форме сотрудничества.
   Убедиться, что при открытии страницы не появляется огромный логотип.
4. Открыть `/purchase`, `/contact`, `/faq` напрямую, затем обновить страницу.
5. Открыть несуществующий URL, например `/does-not-exist`: должна появиться 404.
6. На телефоне проверить меню, ползунки, окно и одинаковую ширину полей формы.
7. Если почта пока не настроена, убедиться, что форма сообщает о недоступности
   отправки и не показывает ложное подтверждение.
8. Проверить `/robots.txt`, `/sitemap.xml` и исходный HTML главной: title,
   description, canonical и Open Graph должны содержать настоящий production-адрес.
9. Проверить сайт через домашний и мобильный интернет. Для аудитории Беларуси
   и России полезна проверка из сетей реальных посетителей.

Дополнительная проверка из терминала; заменить имя реальным:

```bash
curl -I https://имя-проекта.vercel.app
curl -I https://имя-проекта.vercel.app/contact
curl -I https://имя-проекта.vercel.app/does-not-exist
curl https://имя-проекта.vercel.app/api/site-config
```

Ожидаем HTTP 200 для существующих страниц и 404 для неизвестной.
`site-config` содержит публичные параметры, а не почтовый API-ключ.

Сам домен `.vercel.app` — обычный HTTPS-адрес. Собственный домен не является
обязательным условием его работы или индексации. Доступность из конкретной сети
нужно проверять отдельно: корректный DNS не гарантирует отсутствие сетевых ограничений.

## 6. Как включить реальные заявки

Доставка подготовлена через Resend. Она не требует локальной базы.
Создание аккаунта, ключа и проверка адреса отправителя выполняются владельцем.

1. Создать/открыть аккаунт Resend и изучить условия выбранного плана.
2. Для тестовой отправки можно использовать разрешённый сервисом тестовый
   отправитель с учётом ограничений на получателя. Не считать его универсальным
   адресом для публичных заявок.
3. Для обычной работы добавить в Resend собственный домен или почтовый поддомен,
   подтвердить его DNS-записями, выданными сервисом. Это отдельная настройка от
   подключения сайта к Vercel. Существующие MX-записи почтового ящика не удалять.
4. Создать API-ключ с необходимыми правами отправки.
5. В Vercel → Settings → Environment Variables добавить серверные значения:

| Переменная | Значение |
| --- | --- |
| `RESEND_API_KEY` | Ключ из аккаунта Resend |
| `INQUIRY_FROM` | Разрешённый сервисом адрес отправителя |
| `INQUIRY_TO` | Ваш email для получения заявок |
| `OPERATOR_NAME` | Кто отвечает на заявки и обрабатывает контакты |
| `OPERATOR_ADDRESS` | Адрес, если требуется для ваших опубликованных сведений |
| `PRIVACY_EMAIL` | Контакт для вопросов об обработке данных |
| `POLICY_VERSION` | `2026-11-09` либо ваша новая опубликованная редакция |
| `ACCEPT_INQUIRIES` | `true` после завершения настройки |

6. Сверить страницы информации о данных с фактическими условиями обработки,
   хранения писем и используемыми сервисами.
7. Применить новые переменные новым deployment. Для Production и Preview значения
   задаются отдельно; реальные заявки в Preview обычно не нужны.
8. Отправить одну заявку с собственными тестовыми контактами. Проверить ответ
   формы, событие принятия в Resend и получение письма, включая папку «Спам».

Ключ не писать в Git, чат, issue или переменные `VITE_*`.
В браузер попадают только публичные настройки.
[Переменные Vite](https://vite.dev/guide/env-and-mode).

HTTP 202 означает, что почтовый API принял сообщение, а не гарантирует доставку
во входящие. При отказе сервиса сайт возвращает ошибку и сохраняет ввод.
Повторная попытка с тем же содержимым использует Idempotency-Key; Resend хранит
ключи в течение 24 часов. [Идемпотентность Resend](https://resend.com/changelog/idempotency-keys).

Базовый лимит — пять попыток в минуту на клиента **в одном Node-процессе**.
При нескольких экземплярах это не общий лимит. При необходимости настроить
дополнительное правило ограничения на `/api/inquiries` в Vercel Firewall.
Почтовый сервис и ящик тоже имеют собственные ограничения и правила хранения.

## 7. Купил домен на другом сайте — как применить

Покупка домена у другого регистратора совместима с хостингом на Vercel.
Переносить регистрацию в Vercel не нужно. Рекомендуемый простой вариант:
оставить DNS у текущего провайдера и изменить только записи сайта.

1. В проекте Vercel открыть Settings → Domains и добавить купленный домен.
2. Добавить `www`, если нужен и этот вариант. Выбрать основной адрес, например
   `https://example.com`, а `https://www.example.com` направить на него редиректом.
   Оба имени должны быть добавлены и корректно настроены.
3. Vercel покажет необходимые записи именно для вашего проекта.
4. В кабинете регистратора найти DNS / Управление зоной. Если домен делегирован
   другому DNS-провайдеру, записи нужно менять **у него**, а не в неактивной зоне
   регистратора. Узнать текущие NS можно командой `dig NS example.com +short`.
5. Внести точные значения Vercel:

| Назначение | Обычно тип | Имя записи | Значение |
| --- | --- | --- | --- |
| Корневой домен | A | `@` или пустое поле | IP, указанный в Vercel |
| Адрес с www | CNAME | `www` | Цель, указанная в Vercel |
| Проверка владения, если запрошена | TXT | Имя из Vercel | Значение из Vercel |

Не копировать IP/CNAME из старого руководства: Vercel может выдать другое значение.
Не добавлять `https://` в поле значения DNS. Если панель сама дописывает домен к
имени записи, не указывать его дважды.

6. Удалить/заменить конфликтующие записи только для подключаемого веб-имени.
   Не очищать всю DNS-зону: MX, SPF, DKIM, DMARC и записи других поддоменов могут
   обслуживать вашу почту и другие сервисы.
7. Дождаться корректного статуса домена в Vercel и выпуска сертификата.
8. Открыть оба варианта адреса в приватном окне. Проверить редирект и HTTPS.
9. Добавить `SITE_URL=https://ваш-настоящий-домен` для Production и пересобрать сайт.
10. Проверить canonical, Open Graph и sitemap: они должны указывать на новый домен.

[Официальное подключение домена](https://vercel.com/docs/domains/working-with-domains/add-a-domain).

Альтернативный вариант — сменить nameservers на Vercel и управлять всей зоной там.
Для простого подключения он необязателен. Если его выбрать, предварительно
перенести все необходимые записи, иначе могут перестать работать почта и сервисы.
[Управление DNS](https://vercel.com/docs/domains/managing-dns-records).

## 8. DNS, HTTPS и «почему у меня ещё не открывается»

DNS связывает имя с адресом инфраструктуры. HTTPS подтверждает имя сертификатом.
После подключения браузер покажет ваш домен в адресной строке; `.vercel.app`
посетитель не обязан видеть. Сайт остаётся размещённым на Vercel.

Кеши обновляются не одновременно. Изменение отдельных записей часто применяется
быстрее, а при смене NS распространение может занять 24–48 часов.
Не менять записи многократно, пока не проверено, что именно неверно.
[Диагностика доменов](https://vercel.com/docs/domains/troubleshooting).

Vercel автоматически пытается выпустить HTTPS-сертификат после успешной проверки
DNS и продлевает выданный сертификат. Отдельная покупка SSL для этой схемы обычно
не требуется. Регистрация домена продлевается отдельно.
[Сертификаты](https://vercel.com/docs/domains/working-with-ssl).

Проверки с заменой `example.com` на ваш домен:

```bash
dig NS example.com +short
dig A example.com +short
dig CNAME www.example.com +short
dig @1.1.1.1 A example.com +short
dig @8.8.8.8 A example.com +short
curl -I https://example.com
curl -I https://www.example.com
```

Сравнить ответы с настройками проекта. Если возвращается другой IP — проверить
активного DNS-провайдера и конфликтующие записи. Если DNS правильный, а сертификат
не выпускается — проверить статус домена в Vercel и существующие ограничения CAA.
Если в браузере открывается вход Vercel — проверить Deployment Protection.
Если с одного оператора работает, а с другого нет, различить DNS-кеш и сетевую
доступность хостинга. Покупка домена автоматически не устраняет сетевые ограничения.

## 9. SEO после первого запуска и смены домена

- В production нет `noindex`, а основной адрес открыт без авторизации.
- Исходный HTML уже содержит текст страницы, title и description.
- Canonical, sitemap и превью ссылок используют один основной домен.
- Неизвестные страницы возвращают 404.
- Preview не конкурирует с production: сборка Preview получает `noindex`.
- При смене основного адреса по возможности настроить постоянный редирект старого
  домена на новый; не направлять все неизвестные URL на главную.

После выбора постоянного адреса добавить сайт в Google Search Console и
Яндекс Вебмастер, подтвердить владение и отправить sitemap. Файл robots.txt не
защищает приватные сведения. Метатеги и домен сами по себе не обещают конкретную
позицию или срок появления в выдаче.
[Google о JavaScript и SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics).

## 10. Обновления и откат

Изменения сначала проверять локально (`npm test`, `npm run build`,
`npm run test:browser`), затем на Preview. После обновления production-ветки
проверить статус deployment и commit SHA, главную, видеодемонстрации и доступность формы.

Если новая версия сломалась, вернуть предыдущую рабочую production-версию
средствами Vercel либо откатить изменение новым Git-коммитом и развернуть его.
Учесть совместимость с текущими переменными окружения. Force push для обычного
отката не нужен. DNS при каждом обновлении сайта менять не требуется.

Сохранять доступы к GitHub, Vercel, регистратору, DNS-провайдеру и почтовому сервису.
Включить автопродление домена, проверить цену продления и актуальность платёжных
данных. Это разные сервисы даже тогда, когда работают под одним доменом.
