# Vercel, домен и публикация FormworkDesigner

Проверено по официальной документации 2026-11-09.

**Статус:** инструкция для предстоящей миграции. В текущем проекте ещё есть .NET;
описанная ниже конфигурация React/Vite пока не реализована. Проект Vercel не создан,
домен не куплен, DNS не изменён. После реализации настройки и команды нужно
сверить с фактическим README и `vercel.json`.

## 1. Что именно покупать

Домен — адрес, например `formworkdesigner.com`. Хостинг — место, откуда сайт
доставляется посетителю. Их можно приобретать независимо. Подключение домена,
купленного у другого регистратора, к Vercel не требует переноса регистрации.

Для первого просмотра достаточно адреса вида `formworkdesigner.vercel.app`.
Vercel выдаёт адрес в зоне `.vercel.app` при развёртывании; конкретное имя зависит
от доступности. Пример здесь не означает, что имя свободно или уже закреплено.
Для опубликованного лендинга нужно также проверить, что production не закрыт
авторизацией Vercel. [Домены Vercel](https://vercel.com/docs/domains/working-with-domains),
[защита развёртываний](https://vercel.com/docs/deployment-protection).

Для коммерческого сайта рекомендован собственный домен: его удобнее давать
клиентам, размещать в презентациях и сохранять при смене хостинга. Это рекомендация
по бренду и управлению адресом, а не обещание более высоких позиций в поиске.

Купить его можно у Vercel или у отдельного регистратора. У Vercel проще собрать
управление в одном кабинете; отдельный регистратор позволяет независимо выбирать
хостинг и условия продления. Перед покупкой сравнить стоимость первого года и
продления, возможность оплаты, доступность управления и перенос домена. Включить
автопродление и двухфакторную защиту аккаунта. Наличие слова «бесплатный» рядом
с `.vercel.app` не означает бесплатную регистрацию собственного `.com`.

## 2. Тариф хостинга и расходы

Hobby предназначен для личного некоммерческого использования. Лендинг,
продвигающий платную программу, нужно планировать с учётом коммерческого тарифа,
а не предполагать, что Hobby подходит из-за небольшого трафика.
[Условия Hobby](https://vercel.com/docs/plans/hobby).

Перед оплатой проверить текущую цену Pro, включённые ресурсы, дополнительные
места команды и начисления сверх лимитов на [странице тарифов](https://vercel.com/pricing).
Отдельно учесть ежегодное продление домена и возможную оплату почтового сервиса
для заявок или постоянной базы. Настроить доступные уведомления о расходах и
ограничения бюджета; не считать любой тариф безлимитным.

## 3. GitHub и первый деплой

После завершения миграции целевая настройка — React/TypeScript/Vite в корне
репозитория. Node.js нужен для сборки и, при использовании формы, для функций API.
Статические страницы не требуют постоянно работающего Node-сервера.

Планируемые настройки, которые необходимо подтвердить после реализации:

| Поле | Значение |
| --- | --- |
| Git repository | `rsnsrzhn/FormworkDesignerWeb` |
| Root Directory | Корень репозитория |
| Framework Preset | Vite |
| Install Command | `npm ci` |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Node.js | Поддерживаемая Vercel версия, согласованная с `package.json` |

Это штатная схема для [Vite на Vercel](https://vercel.com/docs/frameworks/frontend/vite).

Последовательность действий:

1. Проверить `.gitignore`: исключить `.env*` с секретами, `node_modules`, `dist`,
   `.vercel`, IDE-настройки, логи и временные результаты. Оставить шаблон `.env.example`.
   Нужные публичные медиа должны попадать в сборку, а не оставаться только на ПК.
2. Выполнить чистую установку, проверку типов, необходимые тесты и production-сборку.
3. Отправить проверенные коммиты в GitHub без force push.
4. В кабинете Vercel выбрать добавление проекта, подключить GitHub и импортировать
   нужный репозиторий. Выдать GitHub-интеграции доступ только к нужным репозиториям.
5. Явно проверить production-ветку. Сейчас локальная ветка называется `dev`,
   а опубликованных веток на момент аудита нет. Не предполагать, что production
   уже настроен на `main`: выбрать существующую отправленную ветку осознанно.
6. Сверить параметры таблицы с окончательной структурой репозитория.
7. Добавить необходимые переменные окружения в кабинете Vercel, отдельно для
   Production и Preview, и выполнить развёртывание.
8. Проверить build logs, итоговый commit SHA, статус Ready и адрес сайта.

После подключения Git Vercel может создавать развёртывания по push. Production
следует выбранной production-ветке, остальные ветки и pull requests используются
для предварительного просмотра. Не отправлять непроверенную работу в production-ветку.
[Git-интеграция](https://vercel.com/docs/git),
[окружения](https://vercel.com/docs/deployments/environments).

## 4. Секреты и заявки

Секреты почтового API или базы вводятся в Vercel, не в Git и не в React-код.
Переменные с префиксом `VITE_` могут попасть в браузерную сборку: использовать
их только для публичных значений. Изменение build-time настроек требует новой сборки.
[Переменные Vite](https://vite.dev/guide/env-and-mode).

Способ доставки заявок ещё предстоит выбрать. Возможный простой вариант —
Node.js-функция, отправляющая заявку через почтовый API. Нужны действительный
адрес получателя и настройки выбранного сервиса. Другой вариант — постоянная
управляемая база. Нельзя подтверждать успех формы, если ни доставки, ни сохранения
не произошло. Локальный файл SQLite не подходит как постоянное хранилище
нескольких эфемерных экземпляров функции.

Тестировать форму вымышленными данными: корректная отправка, отказ провайдера,
повторный клик, неверные поля. Проверить получение владельцем, а не только зелёное
сообщение на сайте. Сведения об операторе и политика должны соответствовать
фактическому способу обработки данных.

## 5. Подключение собственного домена

Рекомендуемый старт: купить домен, оставить DNS у выбранного DNS-провайдера и
добавить записи, указанные Vercel. Менять nameservers для обычного лендинга
необязательно.

1. Купить свободное имя; доступность и цена примера `formworkdesigner.com`
   здесь не проверены.
2. В проекте Vercel открыть Settings → Domains и добавить выбранный домен.
3. Добавить вариант с `www`, если он будет использоваться, и выбрать один
   основной адрес. Например, `https://formworkdesigner.com`, а `www` направить
   на него постоянным редиректом. Это пример решения, не обязательный выбор.
4. Взять **точные актуальные значения** из Vercel для этого проекта.
   Обычно корневой домен настраивается через A-запись, `www` — через CNAME.
   Не копировать IP или CNAME из старой статьи.
5. Открыть DNS-кабинет провайдера, чьи nameservers фактически обслуживают домен,
   и добавить указанные записи. Запись у регистратора не поможет, если DNS
   делегирован другому провайдеру.
6. Устранить конфликтующие записи только для подключаемого веб-имени.
   Не удалять все записи зоны. MX и почтовые TXT-записи сохранять.
7. Если Vercel запросит подтверждение владения через TXT, добавить именно
   выданное имя и значение.
8. Дождаться корректного статуса домена в Vercel и выпуска сертификата.

[Подключение домена](https://vercel.com/docs/domains/working-with-domains/add-a-domain).

Альтернатива — делегировать всю DNS-зону Vercel. Тогда все необходимые MX, TXT
и остальные записи нужно перенести до переключения nameservers, иначе могут
перестать работать почта и другие сервисы.
[Управление DNS](https://vercel.com/docs/domains/managing-dns-records).

## 6. Будет ли адрес нормально открываться

Корректно настроенный `.vercel.app` и собственный домен — обычные DNS-имена.
После разрешения имени браузер обращается к инфраструктуре Vercel, получает
HTTPS-соединение и страницу. Покупка собственного домена сама по себе не меняет
хостинг и не гарантирует доступность из любой сети.

Обычные DNS-записи часто обновляются быстрее, но кеши и смена nameservers могут
задержать распространение до 24–48 часов. В это время разные резолверы могут
возвращать разные ответы. Это не причина многократно менять записи наугад.
[Диагностика DNS](https://vercel.com/docs/domains/troubleshooting).

Vercel автоматически пытается выпустить сертификат после добавления домена
и успешной проверки DNS, затем автоматически продлевает выданные сертификаты.
Отдельная покупка SSL для этой схемы обычно не нужна. Продление сертификата
не продлевает регистрацию домена.
[HTTPS и сертификаты](https://vercel.com/docs/domains/working-with-ssl).

Диагностика после подключения, с заменой `example.com` на настоящий домен:

```bash
dig NS example.com +short
dig A example.com +short
dig CNAME www.example.com +short
dig @1.1.1.1 A example.com +short
dig @8.8.8.8 A example.com +short
curl -I https://example.com
curl -I https://www.example.com
```

Сравнить DNS-ответы с настройками проекта. Наличие IP ещё не доказывает, что
работает правильный сайт: проверить HTTPS, содержимое и редиректы. При ошибке
сертификата проверить статус домена, конфликтующие записи и ограничения CAA.

Проверить сайт с телефона через мобильный интернет и из сетей целевых клиентов
в Беларуси и России. Успешный DNS-запрос на компьютере разработчика не доказывает
доступность сайта у всех операторов; собственный домен не обходит автоматически
сетевые ограничения инфраструктуры.

## 7. Проверка сайта после публикации

- Основной адрес и прямые URL страниц открываются без входа в Vercel.
- Известные страницы дают HTTP 200; неизвестный URL — настоящий 404.
- Редиректы не образуют цикл; выбран единственный основной HTTPS-адрес.
- Нет отсутствующих шрифтов, изображений, видео и файлов JavaScript.
- Интерактив работает мышью, клавиатурой и на телефоне, без горизонтального скролла.
- При reduced motion нет обязательного движения; тяжёлая графика не мешает чтению.
- Реальная тестовая заявка доставляется выбранным способом; ошибки не теряют ввод.
- Секреты, установщики и данные пользователей не доступны по публичным URL.
- Production содержит только проверенные возможности и коммерческие условия.

## 8. SEO и появление в поиске

Метатеги — часть подготовки, а не гарантия индексации или позиции по запросу.
Для основного сайта нужны осмысленные русские тексты о проектировании опалубки,
понятные заголовки и отдельные title/description для страниц. Формулировку
«formwork application» стоит использовать в полноценной английской версии,
если она понадобится, а не вставлять бессвязный список ключевых слов.

Проверить, что содержательный HTML, title и description уже приходят в HTTP-ответе,
а не появляются только после JavaScript. Добавить canonical с настоящим доменом,
`sitemap.xml`, корректный `robots.txt`, превью для соцсетей и фактические данные
SoftwareApplication без вымышленных рейтингов или цен.
[Рекомендации Google для JavaScript-сайтов](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics).

Предварительные версии не должны конкурировать с основным доменом в поиске.
Проверить их защиту/`noindex`. Для production убедиться, что `noindex` не осталось.
`robots.txt` не является средством защиты приватных данных.

После выбора окончательного домена добавить сайт в Google Search Console и
Яндекс Вебмастер, подтвердить владение предложенным сервисом способом и отправить
sitemap. Это отдельные действия владельца аккаунтов, ещё не выполненные.

## 9. Обновления и откат

Новый релиз: изменить код в рабочей ветке, проверить сборку и поведение,
посмотреть Preview, затем обновить production-ветку. После деплоя сверить SHA
и провести короткую проверку страниц и заявки.

При проблеме вернуть предыдущую рабочую production-версию средствами Vercel или
откатить изменение новым Git-коммитом с повторным деплоем. Проверить, что предыдущая
версия совместима с действующими переменными окружения и API. Не использовать
переписывание Git-истории как штатный способ отката.

Домен продлевается отдельно от хостинга. Сохранять доступ к регистратору,
DNS-провайдеру, GitHub, Vercel и сервису доставки заявок; это разные точки управления.
