# FormworkDesigner: сайт продукта

## Назначение

Русскоязычный сайт программы для создания чертежей опалубки. Аудитория — потенциальные клиенты в России и Беларуси. Основной результат посещения — заявка на сотрудничество. Проект небольшой, без личного кабинета, регистрации, онлайн-оплаты и публичного скачивания программы.

## Выбранный подход

React + TypeScript для интерфейса, существующий ASP.NET Core (.NET 10) для HTTP API, SQLite для заявок. Один сервер, Docker Compose и Nginx. React собирается в статические файлы; сайт и API работают с одним origin.

Рассмотрены SQLite и PostgreSQL. SQLite выбрана для редких коротких записей заявок и простого обслуживания. PostgreSQL оставлена как возможная миграция при нескольких экземплярах API или существенном росте конкурентных записей. MongoDB не даёт преимуществ для фиксированной структуры заявки.

Медиа хранятся на диске сервера вне Git и Docker-образов, в отдельном постоянном каталоге. S3 не нужен при текущем размере материалов. База находится на локальном постоянном диске, недоступном через HTTP. Установщик не копируется в публичные каталоги.

## Страницы и дизайн

- Главная: название FormworkDesigner, краткое объяснение продукта, основная кнопка заявки, крупная демонстрация интерфейса. Далее чередуются текстовые блоки и реальные медиа: примеры проектов, создание контуров, разбивка на щиты, пересчёт по высоте, ведомость и подготовка листа.
- Покупка: приобретение копии, индивидуальная доработка под процессы компании, стоимость по согласованию после обсуждения сложности. Переход к заявке.
- Связаться: форма заявки вместо вымышленных телефонов, адресов и реквизитов.
- FAQ: отдельная страница, ссылка в футере. Ответы только на подтверждённые вопросы; не обещать неизвестные форматы экспорта, совместимость или условия лицензии.
- Политика обработки персональных данных и условия согласия: самостоятельные адреса со ссылками из формы и футера.

Светлая палитра приложения: почти белый фон, графитовый текст и оранжевый акцент. Локальный кириллический шрифт Golos Text или сопоставимый по читаемости. Ненавязчивая чертёжная сетка и выразительные заголовки. От Sketch — демонстрация интерфейса, от Notion — понятная структура, от Opal — акцент на результате. Без копирования их контента и графики.

Адаптивная вёрстка для телефона и компьютера, клавиатурная навигация, видимый фокус, корректные подписи и сообщения ошибок. Видео с обложками, без звука; не загружать все ролики немедленно. Учитывать prefers-reduced-motion и предоставлять управление воспроизведением. Не закрывать интерфейс продукта декоративным текстом.

## Заявки

Обязательные поля: ФИО, email, телефон России или Беларуси, отдельное согласие на обработку персональных данных. Галочка изначально снята. Не добавлять маркетинговую подписку. Телефон нормализуется к международному виду; клиентская и серверная проверки согласованы. ФИО допускает кириллицу, пробелы, дефисы и другие реальные варианты имён без требования строго трёх слов.

POST /api/inquiries проверяет длины и типы, email, регион телефона, согласие и версию условий. Сохраняет идентификатор, ФИО, нормализованный телефон, email, время UTC и версию принятого согласия. Не сохранять IP в заявке без обоснованной необходимости и не писать контактные данные в логи.

Сервер подтверждает успех только после сохранения. Форма предотвращает повторный клик, показывает ошибки рядом с полями и сохраняет ввод при сетевой ошибке. Ограничение частоты запросов, лимит размера тела, honeypot и проверка origin уменьшают спам. Публичного API чтения заявок нет.

Уведомления по почте пока не согласованы и не входят в базовый объём. Для владельца предусмотрен локальный экспорт заявок через серверную команду в CSV с защитой от формул; доступ через SSH. Это позволяет получать заявки без административного сайта и аккаунтов.

## Персональные данные

Перед подготовкой текста проверить актуальные официальные источники Беларуси на 2026 год. Зафиксировать цель, состав данных, срок хранения, действия с данными, права, отзыв согласия и контакт оператора. Предлагаемый срок для необработанных заявок — 12 месяцев; окончательно фиксируется владельцем перед запуском. Хранение не должно быть бессрочным.

Пользователь пока не предоставил данные оператора и канал отзыва согласия. Их нельзя выдумывать. До заполнения обязательных реквизитов и согласования срока хранения production-приём реальных заявок должен быть отключён явной конфигурацией; тестирование проводится на вымышленных данных. Отдельная страница контактов может содержать только форму, но юридический текст требует сведений об операторе.

Регион сервера и правила обработки данных граждан РФ требуют проверки перед фактическим запуском. Не утверждать, что сам выбор SQLite обеспечивает соответствие законодательству.

## Структура и эксплуатация

FormworkDesignerWeb/ClientApp/: страницы, компоненты, стили, API-клиент и тесты. FormworkDesignerWeb/: API, проверка входных данных, работа с SQLite и конфигурация. tests/: интеграционные проверки сервера. deploy/: Nginx и инструкции. docs/: решения и эксплуатация. Избегать лишних слоёв абстракции для одного сценария.

SQLite: WAL, busy timeout, короткие параметризованные записи, контролируемое создание/обновление схемы. Единственный экземпляр API. Резервные копии через SQLite backup API или другой согласованный безопасный механизм, с документированной проверкой восстановления. Не копировать только основной файл работающей WAL-базы.

HTTPS завершается на reverse proxy. Конфигурация домена, путей, срока хранения и production-приёма вынесена в переменные окружения. В Git — только .env.example без секретов. Docker работает без root, постоянные данные переживают пересоздание контейнеров. Медиа загружаются на сервер отдельно; README объясняет размещение, запуск, обновление и резервирование.
